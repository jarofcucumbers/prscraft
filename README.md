# PRSCraft — телекомунікації для Minecraft

**Minecraft 1.21.1 · NeoForge 21.1.264 · Java 21 · 0.3.0**

[Завантажити prscraft-0.3.0.jar](releases/prscraft-0.3.0.jar) → Download raw file на GitHub → замінити старий JAR у `mods` клієнта й сервера. Додаткові моди не потрібні. Блоки та предмети є у творчій вкладці PRSCraft. Старі світи 0.2.0 зберігають попередній квантований режим.

## Чому TX і RX відрізняються

`sin(10)` — початкова функція, а не обов'язково сигнал, який виходить із TX. У квантованому режимі перед передаванням застосовуються взоркування та квантування. Потім діють обробка, потужність TX, втрати кабелів і шум. Тому порівнювати потрібно відповідні етапи, а не лише початковий синус.

На графіку білий — джерело; жовтий — взоркування; рожевий — сигнал після обробки, перед сумарними втратами лінії; зелений — прийнятий сигнал. RX отримує всі параметри джерела із сервера: **локальної функції, fvz і кількості рівнів у його UI більше немає**. Для прийому потрібні режим RX, та сама RF-несуча, увімкнення та налаштування шуму. Для BPSK додатково потрібні параметри декодера.

Щоб порівняти чисті синуси, виберіть на TX **Аналоговий**, 20 dBm, а на RX вимкніть фізичний шум і поставте штучний RMS=0. Без процесорів амплітуда RX дорівнює TX × `10^(−втрати/20)`: кабель усе ще має затухання. Це очікувана різниця.

## Джерело сигналу

**ПКМ порожньою рукою** відкриває прилад. Кнопка режиму джерела перебирає:

- **Аналоговий:** без взоркування й квантування.
- **Взоркований:** I рід (природне пропускання сигналу всередині імпульсу) або II рід (фіксація значення на початку імпульсу).
- **Квантований:** взоркування, потім рівномірне квантування.
- **Біти (NRZ):** повторювана послідовність 0/1; 1 → +1, 0 → −1; власна символьна швидкість.

Вираз: `sin(10)+0.5*cos(20)-0.2*sin(5)`. `sin(10)` означає `sin(2π·10·t)`, також підтримано `sin(2*pi*10*t)`. До 8 складових, амплітуда кожної ≤10, частоти >0 та ≤1000 Гц. Бітова послідовність — 1–128 символів 0/1, швидкість 1–1000 біт/с.

Для взоркування fvz=1–20000 Гц; `fvz < 2fmax` блокує застосування з помилкою Найквіста. Нульові амплітуди не входять у fmax. `τ/T`=0.05–1; поза імпульсом вихід нульовий. II рід при τ/T=1 — zero-order hold.

Квантування: 2–4096 рівнів між `−Σ|A|` та `+Σ|A|`, округлення до найближчого рівня. При парній кількості рівнів нуль може не входити в сітку. RF-несуча 1–10000 МГц — окремий параметр каналу, не частота sin/cos чи BPSK-піднесучої. Потужність TX: −30…40 dBm.

**Застосувати** зберігає параметри на сервері. Видимість шарів, складових f1–f8 і стан зупинки графіка запам'ятовуються автоматично для кожного блока, також переживають перезапуск світу. Це спільні налаштування блока для всіх гравців. Нове відкриття зупиненого графіка отримує свіжий знімок; для збереження конкретних відліків використовуйте карту даних. Приховування f1 не прибирає її із суми.

## Кабелі та нові процесори

Звичайне з'єднання: `TX → порт → кабелі → порт → RX`.

Із процесором: `TX → порт → кабелі → порт → процесор → порт → кабелі → порт → RX`.

Порт і кабелі вздовж усього маршруту мають бути одного типу: коаксіальні, оптоволоконні або металеві. Підтримані повороти, вертикальні ділянки, розгалуження. Пряме підключення кабелю до приладу без порту не працює.

Нові блоки мають напрямок: **вхід ззаду, вихід спереду**. Позаду помаранчевий роз'єм, зелена позначка зверху показує напрямок виходу. Напрямок задається положенням гравця при встановленні. Зворотне підключення чи вимкнений процесор розриває передачу. До 8 процесорів у маршруті, обробка йде в порядку від TX до RX.

- **Підсилювач:** −40…60 dB; амплітудний множник `10^(gain/20)`; насичення на ±16 умовних одиницях. Це ідеальна модель без власної шумової характеристики.
- **Частотний фільтр:** нижня й верхня межі у Гц, `0 ≤ low < high ≤ 20000`. Low=0 дає ФНЧ; додатний Low — смуговий фільтр. Застосовується до форми сигналу, а не до RF-значення у МГц. Це ідеальний FFT-фільтр скінченного періодичного вікна; роздільність — `1/тривалість вікна`, можливі крайові ефекти. Не аналогова схема зі скінченним спадом і пам'яттю між кадрами.
- **Модулятор:** AM або BPSK. AM: `(1 + depth·x/peak)·cos(2πfc·t)`, глибина 0–1. BPSK: знак вхідного значення на початку символу задає фазу 0/π піднесучої. Для точного передавання бітів вибирайте джерело NRZ і ту саму символьну швидкість. BPSK вимагає `2 ≤ fc/символьна швидкість ≤ 16`.

UI процесора показує його вхід (жовтий) і вихід (зелений); монітор автоматично знаходить доступне джерело вище за трактом, без окремого генератора або RF-налаштування. Графіки змінюються після Застосувати.

## Приклад BPSK

1. TX: **Біти**, `10110010`, 10 символів/с, RF=100 МГц, живлення ввімкнене → Застосувати.
2. Підключіть **модулятор** у правильному напрямку між двома кабельними ділянками.
3. Модулятор: BPSK, піднесуча **100 Гц**, **10 символів/с**, увімкнено → Застосувати.
4. RX: RF=100 МГц, увімкнено; виберіть **декодер BPSK**, ті самі 100 Гц і 10 символів/с → Застосувати.
5. Для першої перевірки вимкніть фізичний шум і поставте штучний RMS=0. У рядку над графіком відобразяться декодовані `10110010`. Потім збільшуйте шум і спостерігайте помилки.

Когерентний декодер припускає відомі частоту, фазу й часову сітку; автоматичного пошуку несучої, відновлення синхронізації, пакетного протоколу та корекції помилок поки немає. AM-демодулятор ще не додано. Розрахунок іде по 512 відліках скінченного вікна, не безперервним RF-потоком. Для довгих ланцюгів модуляторів вікно може показувати лише частину послідовності.

## Паперові шаблони

У UI приладу натисніть **Шаблони / записи** — відкриється справжній інвентар зі слотами та інвентарем гравця.

1. Спочатку застосуйте бажані параметри приладу, налаштуйте видимість графіка.
2. У верхній слот вставте **один аркуш паперу**.
3. Натисніть **Записати налаштування на папір** — папір перетвориться на предмет-шаблон.
4. Заберіть шаблон і вставте у відповідний слот іншого приладу **того самого виду**. Налаштування, режим і вигляд графіка застосуються автоматично. Є також кнопка ручного застосування.

Шаблони передавача працюють для передавачів (зокрема RX-профілі), підсилювача — для підсилювачів тощо. Перезапис шаблону виконується тією самою кнопкою. Предмет не витрачається при застосуванні. Вміст слотів зберігається й випадає при руйнуванні приладу.

## Запис і CSV

У нижній слот вставте **Карту даних**. Кнопка запису зберігає **новий серверний знімок із 512 відліків** разом із конфігурацією, часом і параметрами лінії. Повторне натискання перезаписує карту. Це знімок у момент натискання, а не безперервний логер і не копія раніше зупиненого графіка.

- **Перегляд** відкриває саме збережену осцилограму в режимі читання, навіть коли живий сигнал уже змінився.
- **CSV** записує файл на комп'ютері клієнта в `<тека гри>/prscraft/recordings/`; шлях з'являється в чаті. Наявні файли не перезаписуються.
- Колонки: `time_seconds, original, sampled, tx_output, channel_input, received`. RX-карта містить прийнятий сигнал, TX-карта — власний знімок джерела й опорного виходу. У процесорі також можна зберегти знімок тракту.

Карту можна витягти, зберігати в скрині, передавати іншим гравцям та вставляти в інший прилад для перегляду/експорту. Рецепт: ` R ` / `CPC` (R — редстоун, C — мідь, P — папір). Закриття меню носіїв повертає до UI приладу.

## Затухання, шум і межі моделі

1 блок = 1 метр. Коаксіал: 0.20 dB/м на 100 МГц, роз'єм 1 dB; волокно: 0.003 dB/м, роз'єм 0.5 dB; метал: 0.50 dB/м, роз'єм 2 dB. Кожна ділянка між активними пристроями має два роз'єми. Для металу й коаксіалу втрати/м множаться на `sqrt(RF/100)`; для волокна множник =1 (передбачається електрооптичний перетворювач).

У цій навчальній моделі DSP-процесори працюють у заданому порядку, **сумарні втрати лінії й шум RX застосовуються після них**. Втрати ще не розподілені фізично між окремими каскадами, тому перевантаження підсилювача не є точною моделлю реального багатокаскадного тракту. Опорна амплітуда відповідає 20 dBm (100 мВт); фінальний коефіцієнт `10^((Ptx−20−втрати)/20)`.

На RX незалежно вмикаються тепловий шум при 290 K і наведення від інших TX у кубі ±4 блоки та задається штучний гаусівський RMS 0–2. Компоненти додаються за потужністю. Фізичний шум також змодельований; мод не вимірює апаратний шум комп'ютера. Волокно не має електромагнітних наведень, але його приймач має тепловий шум.

Пошук — до 256 вузлів на середовище; чанки не завантажуються примусово. Сервер оновлює відкритий UI приблизно раз на секунду. Розглядаються найкоротші маршрути, серед джерел обирається найбільша оцінка потужності з урахуванням підсилювачів (без точної оцінки насичення та спектра). Відбиття, хвильовий опір, затримка поширення, екранування стінами, бездротовий зв'язок і реальні електричні схеми поки не реалізовані.

## Аналізатор і розробка

ПКМ **Аналізатором лінії** по порту дає діагностику локальної кабельної ділянки без зміни властивостей; активні процесори показуються окремо. Кабелі, аналізатор, карта даних і нові процесори мають рецепти. Передавач і порти поки беруться з творчої вкладки.

```sh
./gradlew build
./gradlew runGameTestServer
./gradlew runClient
./gradlew runServer  # EULA приймає користувач
```

Збірка: `build/libs/prscraft-0.3.0.jar`; копія та SHA-256 — у `releases/`. 22 JUnit-тести перевіряють математику, спектральний фільтр, BPSK із шумом і CSV; 7 GameTest — реальний маршрут, напрямки процесорів, прийом BPSK, шаблони, записи, збереження графіка та незмінність даних від аналізатора. Тестові класи й структури не входять до релізного JAR. Вигляд нових екранів у графічному клієнті в цьому хмарному середовищі ще не перевірений.

Моделі JSON використовують стандартні текстури Minecraft та редагуються у Blockbench як Java Block/Item.

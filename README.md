# PRSCraft — телекомунікації для Minecraft

**Minecraft 1.21.1 · NeoForge 21.1.264 · Java 21 · версія 0.2.0**

## Встановлення

[Завантажити prscraft-0.2.0.jar](releases/prscraft-0.2.0.jar) → **Download raw file** на GitHub → покласти у `mods` клієнта та сервера. Видаліть стару версію мода з `mods`. Інші моди не потрібні.

## Передавач і UI

У творчому режимі відкрийте вкладку PRSCraft. Поставте два радіоприлади. **ПКМ порожньою рукою** відкриває редактор; усі зміни потрібно підтвердити кнопкою **Застосувати**. Налаштування перевіряє й зберігає сервер; вони переживають перезапуск світу. UI не зупиняє гру, масштабується до вікна й підтримує українську та англійську мови.

- **Вираз:** `sin(10)+0.5*cos(20)-0.2*sin(5)`. Число в дужках — частота у Гц: `sin(10)` означає `sin(2π·10·t)`. Підтримано й запис `sin(2*pi*10*t)`. До 8 складових; амплітуда кожної до 10, частота >0 і ≤1000 Гц. Зміна числа змінює частоту відповідної складової. Довільні математичні вирази, фази й функції поза sin/cos не підтримуються.
- **fvz:** частота взоркування, 1–20000 Гц. При `fvz < 2fmax` показується помилка Найквіста, застосування блокується і налаштування на сервері залишаються попередніми. Нульова амплітуда не входить у fmax.
- **Взоркування I роду:** природне — сигнал проходить протягом відкритого імпульсу. **II роду:** значення фіксується на початку імпульсу й тримається до його завершення. `τ/T` задає частку періоду, коли імпульс відкритий (0.05–1). При τ/T=1 II рід працює як zero-order hold. Поза імпульсом вихід дорівнює нулю.
- **Квантування:** після взоркування, 2–4096 рівнів, рівномірна сітка між `−Σ|A|` та `+Σ|A|`, округлення до найближчого рівня. При парній кількості рівнів нуль може не входити в сітку.
- **TX/RX:** вибір передачі або прийому; **Живлення** вмикає/вимикає прилад. TX потужність: −30…40 dBm. Несуча: 1–10000 МГц — це окрема частота від частот sin/cos.

Графік показує окремі складові (кольори f1–f8), суму (білий), взоркований (жовтий), квантований (рожевий) і прийнятий (зелений) сигнали. Кожен шар можна приховати. Кнопки f1–f8 лише керують видимістю; вони не прибирають складову із суми. Вісь X — секунди; Y — умовні амплітудні одиниці. Вікно автоматично обмежене 4 періодами найвищої частоти та 32 періодами взоркування, щоб імпульси залишалися видимими. **Зупинити** фіксує поточний знімок прийому.

## Кабелі й передача

З'єднання: **TX → порт → кабелі того самого типу → порт → RX**. Порт може прилягати до приладу з будь-якого боку. Кабель сам змінює модель і форму відповідно до сусідів; підтримуються повороти, вертикальні ділянки та розгалуження. Несумісні типи не з'єднуються. Пряме підключення кабелю до приладу без порту не працює.

На RX виберіть ту саму несучу частоту, що й на TX, та натисніть Застосувати. Обидва прилади мають бути ввімкнені. Приймач шукає найкоротші маршрути у кожному середовищі й обирає доступний TX із найбільшою оцінкою прийнятої потужності. При розриві лінії, несумісній частоті або вимкненому TX прийом зникає. Довжина — кількість метрів між центрами блоків уздовж маршруту; 1 блок = 1 метр.

Обчислення виконуються сервером на запит відкритого UI приблизно раз на секунду. Сервер формує 512 відліків прийнятого сигналу та надсилає їх клієнту для графіка. Це навчальна передача сигналу, а не передача довільних предметів чи пакетів користувацьких даних. Пошук обмежений 256 вузлами на тип середовища; незавантажені чанки не завантажуються примусово. Через обрізання великої мережі частина TX може бути недоступна.

| Лінія | Втрати/м на 100 МГц | Один роз'єм | Наведення |
|---|---:|---:|---:|
| Коаксіальна | 0,20 dB | 1 dB | 0,05 |
| Оптоволоконна | 0,003 dB | 0,5 dB | 0 |
| Металева | 0,50 dB | 2 dB | 0,35 |

Втрати: два роз'єми + довжина × втрати/м × `sqrt(несуча/100)`. Для волокна частотний множник =1: передбачається електрооптичний перетворювач. Амплітудний коефіцієнт: `10^((Ptx−20−втрати)/20)`; одиниця сигналу відповідає опорним 100 мВт (20 dBm). Значення навчальні, не паспорт реального кабелю.

## Шум

На **RX** доступні незалежні налаштування:

- **Тепловий + наведення:** фізична модель теплового шуму `kTB` при 290 K (B=fvz/2) та наведень від інших ввімкнених TX у кубі ±4 блоки. Перекриття несучих має умовну ширину 40 МГц; сила наведення залежить від типу лінії й відстані. Волокно не має електромагнітного наведення, але приймач має тепловий шум.
- **Штучний RX RMS:** додатковий гаусівський білий шум із вибраним RMS 0–2. Значення 0 вимикає його. Компоненти шуму додаються за потужністю.

«Фізичний» шум тут також обчислюється моделлю; мод не вимірює справжній шум апаратури комп'ютера. Це еквівалентний шум каналу в смузі прийому, утримуваний між відліками, а не повний RF-симулятор. Геометрія стін, відбиття, хвильовий опір, реальне екранування та бездротовий зв'язок ще не реалізовані. AM/FM не додаються: взоркування I/II роду — окремі операції.

## Аналізатор лінії

Окремий предмет **Аналізатор лінії**: **ПКМ ним по порту** показує діагностику в чаті, не відкриваючи редактор і не змінюючи жодних властивостей. Звіт містить тип мережі, кількість вузлів, координати та режими до 8 підключених приладів, несучу, довжину маршруту, втрати й оцінку потужності TX на вимірюваному порту. Для RX потужність не оцінюється. Ліміт пошуку — 256 вузлів; при його досягненні показується попередження.

Аналізатор і всі три кабелі мають рецепти. Передавач і порти поки доступні у творчому режимі. Для аналізатора рецепт: ` R ` / `IGI` / ` C ` (R — редстоун, I — залізо, G — скло, C — мідь). Для 8 кабелів: верхній ряд із трьох залізних злитків (коаксіал), скла (волокно) або мідних злитків (метал); другий ряд — три редстоуни.

## Розробка й перевірки

```sh
./gradlew build                # JAR + JUnit
./gradlew runGameTestServer    # інтеграційні перевірки у Minecraft
./gradlew runClient            # інтерактивний клієнт
./gradlew runServer            # звичайний сервер; EULA приймає користувач
```

Зібраний файл: `build/libs/prscraft-0.2.0.jar`. Копія для завантаження та SHA-256 — у `releases/`.

JUnit перевіряє формули, вирази, Найквіста, обидва види взоркування, квантування, шум, затухання та обхід мережі. GameTest перевіряє поворот/розрив кабелю, несумісність частоти й середовища, збереження блока та відсутність змін від аналізатора. GameTest-класи й тестова структура не входять до готового JAR. Інтерактивний вигляд UI в графічному клієнті ще не перевірений у цьому хмарному середовищі.

Моделі Minecraft JSON використовують стандартні текстури; їх можна редагувати у Blockbench як Java Block/Item. Кабелі мають окремі центральні й з'єднувальні частини для всіх шести напрямків, аналізатор — власну предметну модель.
